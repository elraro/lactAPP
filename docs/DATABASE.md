# Database

> **Status: APPROVED 2026-10-08.** Implemented in `server/migrations/00001_init.sql`,
> which is authoritative for exact column definitions.

PostgreSQL 17. All instants are `timestamptz` (stored UTC). All primary keys are
UUIDs; rows that originate on a device use client-generated **UUIDv7**.

## 1. Entity overview

```
families ──< users ──< devices ──< refresh_tokens
    │           └──< invites
    ├──< babies ──< events
    ├──< applied_mutations
    └──< ai_analyses
```

Syncable entities (replicated to devices): `babies`, `events`, and `families`
(read-only on devices). Everything else is server-only.

## 2. Sync columns

Every syncable table has:

| Column | Meaning |
|---|---|
| `family_id` | Tenant. Part of every index and every query. |
| `seq bigint` | Value of the family's change counter when the row was last written. Drives the pull feed. |
| `version int` | Starts at 1, +1 on every accepted mutation. Clients echo it as `base_version`. |
| `created_at`, `updated_at` | **Server** clock. |
| `deleted_at` | Tombstone. Rows are never physically deleted (data volume is tiny; a device that was offline for months still converges). |
| `created_by_user_id`, `created_by_device_id`, `updated_by_user_id`, `updated_by_device_id` | Attribution ("recorded by Dad's phone"). |

`seq` is allocated with
`SELECT … FROM families WHERE id = $1 FOR UPDATE` at the start of the writing
transaction and `sync_seq + 1` written back before commit. The row lock serializes writers of one family, so
sequence numbers become visible in order and a reader can never skip a change that
commits late. (A plain global sequence has exactly that bug.) Contention is
irrelevant at family scale.

## 3. Tables

```sql
CREATE EXTENSION IF NOT EXISTS citext;

CREATE TABLE families (
  id          uuid PRIMARY KEY,
  name        text        NOT NULL,
  timezone    text        NOT NULL,              -- IANA; default reporting zone
  ai_enabled  boolean     NOT NULL DEFAULT false,
  sync_seq    bigint      NOT NULL DEFAULT 1,    -- change counter
  sync_epoch  uuid        NOT NULL,              -- changes only if history is rewritten (restore)
  seq         bigint      NOT NULL DEFAULT 1,    -- this row's own position in the feed
  version     int         NOT NULL DEFAULT 1,
  created_at  timestamptz NOT NULL DEFAULT now(),
  updated_at  timestamptz NOT NULL DEFAULT now()
);

CREATE TABLE users (
  id            uuid PRIMARY KEY,
  family_id     uuid        NOT NULL REFERENCES families(id),
  email         citext      NOT NULL UNIQUE,
  display_name  text        NOT NULL,
  password_hash text,                             -- Argon2id PHC string; NULL until setup code redeemed
  created_at    timestamptz NOT NULL DEFAULT now(),
  updated_at    timestamptz NOT NULL DEFAULT now(),
  disabled_at   timestamptz
);

CREATE TABLE devices (
  id           uuid PRIMARY KEY,                  -- generated by the app on first launch
  family_id    uuid        NOT NULL REFERENCES families(id),
  user_id      uuid        NOT NULL REFERENCES users(id),
  name         text        NOT NULL,              -- e.g. "Pixel 8"
  platform     text        NOT NULL,              -- "android"
  app_version  text        NOT NULL,
  created_at   timestamptz NOT NULL DEFAULT now(),
  last_seen_at timestamptz NOT NULL DEFAULT now(),
  revoked_at   timestamptz
);

CREATE TABLE refresh_tokens (
  id           uuid PRIMARY KEY,
  device_id    uuid        NOT NULL REFERENCES devices(id),
  user_id      uuid        NOT NULL REFERENCES users(id),
  token_hash   bytea       NOT NULL UNIQUE,       -- SHA-256 of the token
  replaced_by  uuid        REFERENCES refresh_tokens(id),
  created_at   timestamptz NOT NULL DEFAULT now(),
  used_at      timestamptz,
  expires_at   timestamptz NOT NULL,
  revoked_at   timestamptz
);

CREATE TABLE invites (                            -- also used for first-user password setup
  id           uuid PRIMARY KEY,
  family_id    uuid        NOT NULL REFERENCES families(id),
  code_hash    bytea       NOT NULL UNIQUE,
  purpose      text        NOT NULL CHECK (purpose IN ('join_family','set_password')),
  user_id      uuid        REFERENCES users(id),  -- target user for set_password
  created_by   uuid        REFERENCES users(id),
  created_at   timestamptz NOT NULL DEFAULT now(),
  expires_at   timestamptz NOT NULL,
  redeemed_at  timestamptz
);

CREATE TABLE babies (
  id             uuid PRIMARY KEY,
  family_id      uuid        NOT NULL REFERENCES families(id),
  name           text        NOT NULL CHECK (length(name) BETWEEN 1 AND 100),
  date_of_birth  date        NOT NULL,
  sex            text        CHECK (sex IN ('female','male')),   -- optional; only for future percentiles
  notes          text        CHECK (length(notes) <= 4000),
  -- sync columns (§2)
  seq bigint NOT NULL, version int NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz,
  created_by_user_id uuid NOT NULL REFERENCES users(id),
  created_by_device_id uuid NOT NULL REFERENCES devices(id),
  updated_by_user_id uuid NOT NULL REFERENCES users(id),
  updated_by_device_id uuid NOT NULL REFERENCES devices(id),
  UNIQUE (id, family_id)                          -- target of the composite FK below
);

CREATE TABLE events (
  id          uuid PRIMARY KEY,
  family_id   uuid        NOT NULL,
  baby_id     uuid        NOT NULL,
  type        text        NOT NULL CHECK (type IN ('bottle','diaper','sleep','measurement','note')),
  started_at  timestamptz NOT NULL,               -- when it happened / began
  ended_at    timestamptz,                        -- sleep end, optional bottle end
  timezone    text        NOT NULL,               -- IANA zone of the recording device

  -- bottle
  amount_ml   int         CHECK (amount_ml BETWEEN 1 AND 1000),
  milk_kind   text        CHECK (milk_kind IN ('formula','breast_milk','mixed')),
  -- diaper
  diaper_kind text        CHECK (diaper_kind IN ('wet','dirty','both')),
  -- sleep
  sleep_kind  text        CHECK (sleep_kind IN ('nap','night')),
  -- measurement
  weight_g    int         CHECK (weight_g  BETWEEN 200 AND 60000),
  height_mm   int         CHECK (height_mm BETWEEN 200 AND 2000),
  head_mm     int         CHECK (head_mm   BETWEEN 100 AND 800),

  notes       text        CHECK (length(notes) <= 4000),

  -- sync columns (§2)
  seq bigint NOT NULL, version int NOT NULL DEFAULT 1,
  created_at timestamptz NOT NULL DEFAULT now(), updated_at timestamptz NOT NULL DEFAULT now(),
  deleted_at timestamptz,
  created_by_user_id uuid NOT NULL REFERENCES users(id),
  created_by_device_id uuid NOT NULL REFERENCES devices(id),
  updated_by_user_id uuid NOT NULL REFERENCES users(id),
  updated_by_device_id uuid NOT NULL REFERENCES devices(id),

  FOREIGN KEY (baby_id, family_id) REFERENCES babies (id, family_id),
  CHECK (ended_at IS NULL OR ended_at >= started_at),
  CHECK (
    (type = 'bottle'      AND amount_ml IS NOT NULL
        AND num_nonnulls(diaper_kind, sleep_kind, weight_g, height_mm, head_mm) = 0) OR
    (type = 'diaper'      AND diaper_kind IS NOT NULL AND ended_at IS NULL
        AND num_nonnulls(amount_ml, milk_kind, sleep_kind, weight_g, height_mm, head_mm) = 0) OR
    (type = 'sleep'       AND sleep_kind IS NOT NULL
        AND num_nonnulls(amount_ml, milk_kind, diaper_kind, weight_g, height_mm, head_mm) = 0) OR
    (type = 'measurement' AND num_nonnulls(weight_g, height_mm, head_mm) >= 1 AND ended_at IS NULL
        AND num_nonnulls(amount_ml, milk_kind, diaper_kind, sleep_kind) = 0) OR
    (type = 'note'        AND notes IS NOT NULL AND ended_at IS NULL
        AND num_nonnulls(amount_ml, milk_kind, diaper_kind, sleep_kind, weight_g, height_mm, head_mm) = 0)
  )
);

CREATE INDEX events_feed     ON events (family_id, seq);
CREATE INDEX events_timeline ON events (baby_id, started_at DESC, id DESC);
CREATE INDEX babies_feed     ON babies (family_id, seq);

CREATE TABLE applied_mutations (                  -- idempotency log
  family_id      uuid        NOT NULL REFERENCES families(id),
  mutation_id    uuid        NOT NULL,
  device_id      uuid        NOT NULL,
  entity         text        NOT NULL,
  entity_id      uuid        NOT NULL,
  status         text        NOT NULL,            -- applied | rejected
  error_code     text,
  merged         boolean     NOT NULL DEFAULT false,
  applied_at     timestamptz NOT NULL DEFAULT now(),
  PRIMARY KEY (family_id, mutation_id)
);

CREATE TABLE ai_analyses (                        -- Phase 8, not created yet
  id           uuid PRIMARY KEY,
  family_id    uuid        NOT NULL REFERENCES families(id),
  baby_id      uuid        NOT NULL,
  kind         text        NOT NULL,
  range_days   int         NOT NULL,
  locale       text        NOT NULL,
  provider     text        NOT NULL,
  model        text        NOT NULL,
  context_hash bytea       NOT NULL,              -- SHA-256 of the exact context sent
  result       jsonb       NOT NULL,
  created_by   uuid        NOT NULL REFERENCES users(id),
  created_at   timestamptz NOT NULL DEFAULT now(),
  FOREIGN KEY (baby_id, family_id) REFERENCES babies (id, family_id)
);
```

## 4. Design notes

- **Why one `events` table.** All event types share identity, baby, time, notes
  and the sync columns; the type-specific part is one to three scalar columns.
  A single table gives one timeline query, one change feed, and one Room table.
  The per-type CHECK keeps it as strict as separate tables would be. Adding a type
  later = one migration adding columns and extending the CHECKs.
- **Durations are never stored.** Sleep and bottle duration are `ended_at − started_at`.
  An open sleep session is a `sleep` row with `ended_at IS NULL`.
- **Sleep/Wake in the timeline** are two rendered rows derived from one session,
  not two events. This makes "wake without sleep" unrepresentable.
- **Measurements are events** so they appear on the timeline and sync like
  everything else. Integers in base units (g, mm, ml) avoid float drift.
- **Composite FK `(baby_id, family_id)`** makes it impossible at the database
  level for an event to point at another family's baby, even if application code
  has a bug.
- **Overlapping sleep** is deliberately *not* an exclusion constraint — see
  [SYNC.md](SYNC.md) §7.
- **Retention.** Nothing is pruned yet. Planned (Phase 9): drop `applied_mutations`
  rows older than 90 days and used refresh tokens / expired invites older than 30 days.

## 5. Android (Room) mirror

Room holds `babies`, `events` and a one-row `family` table with the same columns,
instants as epoch milliseconds (`Long`), plus:

```
pending_mutations(sequence PK autoincrement, mutation_id UNIQUE, entity, entity_id, op,
                  fields_json, base_version, created_at, sent, error_code)
sync_state(id=1, cursor, last_success_at, server_time_offset_ms)
```

`sequence` is the send order. `sent` marks a mutation that may have reached the server
and must never change again; `error_code` marks a permanent rejection. A row's
"not yet synced" / "failed" indicator is derived from this table, not stored on the
entity. `version = 0` on an entity means the server has not seen it yet. The sync epoch
is inside the opaque cursor. The exported schema is in `android/app/schemas/`.
